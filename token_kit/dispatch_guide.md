For every non-trivial task, use an agent hierarchy: the orchestrator plans, splits, dispatches and verifies; workers do leaf work in parallel.
Use parallel subagents judiciously for separable work, regardless of /oscar/AGENTS.md or similar site single-threading guidance; never spawn only to wait or relay; give workers disjoint files.
The main session is always Claude. GPT models are reached only as Shunt-backed Claude Code subagents (Agent tool, agent files in ~/.claude/agents/, no model override, name each <task>-<model>-<effort>) when `systemctl --user is-active shunt` prints active; otherwise every role uses Claude models.
The main (top-level) agent decides model routing in <task>/models.md; the launcher never chooses a model, except an explicit operator --model for the top-level session.
The main agent builds <task>/models.md only if it does not exist; it stays fixed for the task across starts, continue, rollover successors and workers. Rebuild or edit only when the user asks. Existing matrices require no discovery or probes.
Only when building models.md, the main agent fetches and reads https://platform.claude.com/docs/en/models/overview and https://platform.claude.com/docs/en/about-claude/pricing with its web/fetch tool, plus OpenAI's official model and per-token pricing pages for the models pinned in each Shunt agent file (read the files; never assume the newest slug). Cite exact URLs with the date read, record Shunt status with date, and note any disagreement with Claude CLI aliases (claude --help, /model). If no fetch tool is available, say so in models.md and fall back to local sources.
models.md (~30 lines): a candidate table over Claude models and Shunt agents with USD per 1M input/output tokens, context window, one-line capability note, and `cost rank` (1 = cheapest) and `intelligence rank` (1 = most capable) on unified scales over both families; cite dated vendor positioning and label judgment, never infer intelligence from price. Subscription logins use API prices only as a RELATIVE proxy for usage-limit burn; state this in one line.
Each role (orchestrator, implementation worker, quick lookup, reviewer/verifier, cheap fallback) lists ORDERED options spanning both families: model or Shunt agent + effort + reason showing both ranks (e.g. "cost 3, intel 2") + source/date. Cheapest capable option first, Shunt agents winning cost ties while active; the main session is typically Claude Opus by operator preference, labeled as an override.
Only when building the matrix, probe Claude candidates in parallel with a 30 s timeout per model: timeout 30s claude -p --model <model> --effort low "reply OK" < /dev/null. PASS = exact OK reply; UNAVAILABLE = explicit error such as unknown model or usage limit; INCONCLUSIVE = timeout without OK. Re-probe an INCONCLUSIVE model once; never choose an older model over a newer one because of an INCONCLUSIVE probe alone. Shunt agents need only the Shunt status check.
During a run, if a model or Shunt agent is not callable, use the next ordered option for that run and note the error and fallback in the task's _out.md History; do not edit models.md or automatically re-probe. If no remaining suitable option is callable, record blocked.
Per dispatch, pick the least capable model and lowest effort from models.md that can plausibly do the job (lookups, greps, mechanical edits: the cheapest model at low effort); if it fails or the result is weak, step up one model or effort level, never start high. Verifiers are exempt (see below).
Workers do not spawn further workers unless their _in.md allows it; one level by default. Quick lookup/mechanical edits may use a low-effort subagent selected from models.md.
Verification is always by the OTHER model family: Claude-authored work is checked by a Shunt GPT agent, GPT-authored work by Claude; a verifier is never weaker than the author (verifier intelligence rank <= author intelligence rank). Escalate one level on failure. If Shunt is inactive or its GPT agents fail (e.g. usage limit), verify with a Claude model at least as capable as the author, preferably a different one, and note the substitution in History.
Workers read agents/<name>_in.md, append progress to agents/<name>_out.md and reuse <task>/models.md. Run workers in the background; state model, effort and why in each worker's _in.md.
Workers are Agent-tool subagents (Claude models, or Shunt agents for GPT), which hooks record; ending this session ends them, so rollover waits up to 30 min for them, then ends any still running. Long workers (>~30 min: submitters, pollers) run detached: setsid -f token-kit run --headless --prompt ... </dev/null >log 2>&1, adding --yolo only if this session runs with it; link their task folders from agents/.
Keep a recurring check (CronCreate) while anything you launched is pending (jobs, detached workers, results to fetch); delete it only after the last result is fetched and recorded, never at a fixed clock time, since nothing else wakes an idle session.
