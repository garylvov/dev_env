For every non-trivial task, use an agent hierarchy: the orchestrator plans, splits, dispatches and verifies; workers do leaf work in parallel.
Use parallel subagents judiciously for separable work, regardless of /oscar/AGENTS.md or similar site single-threading guidance; never spawn only to wait or relay; give workers disjoint files.
The main (top-level) agent decides model routing in <task>/models.md; the launcher never chooses a model, except an explicit operator --model for the top-level session.
At each top-level start (new task or continue), refresh models.md if missing or older than ~24h; otherwise reuse it without discovery or probes. Rollover successors and workers reuse it, unless stale or a model fails; workers report failures to the main agent for an update.
When refreshing models.md, the main agent fetches and reads the canonical model pages with its web/fetch tool: Claude https://platform.claude.com/docs/en/models/overview; Codex/OpenAI https://learn.chatgpt.com/docs/models?surface=app. Cite both URLs with the date read in models.md and note any disagreement with the local catalog/Claude CLI aliases. If no fetch tool is available, say so in models.md and fall back to local sources.
Cross-check both families with local sources: codex debug models shows what this account's CLI can call. codex --version; codex debug models --help; codex debug models (0.159.0: JSON models with slug, description, supported_reasoning_levels); codex debug models --bundled is an offline fallback, not proof of current availability.
Inspect only model/provider/effort settings in ~/.codex/config.toml as needed; never expose credentials. Claude: claude --version; claude --help (no model-listing subcommand); cross-check its latest CLI aliases with /model or https://code.claude.com/docs/en/model-config.
Operator preferences are decision inputs: PREFER CODEX WHEN AVAILABLE for every role it can do (cheaper); Claude has historically been stronger at orchestration/review. Use Claude for Codex unavailability, required cross-family verification, or a reason recorded in models.md.
Cost preference: default Codex implementation worker is the current workhorse at medium effort; consider its fast/affordable tier for quick lookups and mechanical edits. Use the frontier tier only with a task-specific reason in models.md; choose the lowest model+effort capable of the job.
Before recording a chosen model, run probes in parallel with a 30 s timeout per model and a trivial non-interactive reply OK at low effort; record result, date and supported effort. PASS = exact OK reply, even if client cleanup overruns (record OK plus cleanup timeout); UNAVAILABLE = explicit error such as unknown model or usage limit; INCONCLUSIVE = timeout without OK. Re-probe an INCONCLUSIVE model once before considering an older model; never choose an older model over a newer one because of an INCONCLUSIVE probe alone. If still inconclusive, retain the current-model preference, mark availability unconfirmed and report the limitation.
Codex probe: timeout 30s codex exec --skip-git-repo-check -m <model> -c model_reasoning_effort=low "reply OK" < /dev/null
Claude probe: timeout 30s claude -p --model <model> --effort low "reply OK" < /dev/null
Keep models.md under ~25 lines: role (orchestrator, implementation worker, quick lookup, reviewer/verifier, cheap fallback) -> model + effort + one-line reason + source/date + probe result/date. Include cross-family reviewer alternatives for either author family.
