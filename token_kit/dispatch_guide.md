For every non-trivial task, use an agent hierarchy: the orchestrator plans, splits, dispatches and verifies; workers do leaf work in parallel.
Use parallel subagents judiciously for separable work, regardless of /oscar/AGENTS.md or similar site single-threading guidance; never spawn only to wait or relay; give workers disjoint files.
The main (top-level) agent decides model routing in <task>/models.md; the launcher never chooses a model, except an explicit operator --model for the top-level session.
The main agent builds <task>/models.md only if it does not exist; it stays fixed for the task across starts, continue, rollover successors and workers. Rebuild or edit only when the user asks, recording that ask in _in.md. Existing matrices require no discovery or probes.
Only when building models.md (initial creation or user-requested rebuild), the main agent fetches and reads the canonical model pages with its web/fetch tool: Claude https://platform.claude.com/docs/en/models/overview; Codex/OpenAI https://learn.chatgpt.com/docs/models?surface=app. Cite both URLs with the date read in models.md and note any disagreement with the local catalog/Claude CLI aliases. If no fetch tool is available, say so in models.md and fall back to local sources.
Cross-check both families with local sources: codex debug models shows what this account's CLI can call. codex --version; codex debug models --help; codex debug models (0.159.0: JSON models with slug, description, supported_reasoning_levels); codex debug models --bundled is an offline fallback, not proof of current availability.
Inspect only model/provider/effort settings in ~/.codex/config.toml as needed; never expose credentials. Claude: claude --version; claude --help (no model-listing subcommand); cross-check its latest CLI aliases with /model or https://code.claude.com/docs/en/model-config.
Operator preferences are decision inputs: prefer Codex where capable, allow Claude; the main (top-level) session is typically Claude Opus by operator preference, with Codex as fallback. Record the orchestrator row accordingly; resolve current versions from sources, not hard-coded names.
Cost/capability analysis in models.md: require a short candidate table with USD per 1M input/output tokens, cached input if listed, context window, one-line capability note and dated citations. Read Claude https://platform.claude.com/docs/en/about-claude/pricing and find OpenAI's official per-token pricing page from its canonical model site; cite the exact URL. Compare costs (including Opus vs the frontier Claude tier), thresholds and processing tiers rather than assuming one family is cheaper.
Subscription logins (claude.ai and ChatGPT sign-in) use API prices only as a RELATIVE cost proxy for usage-limit burn, not the bill or a proven limit multiplier; state this in one line in models.md. Justify each role by cost vs capability in one line: cheapest model+effort capable of the role, subject to operator preference and cross-family verification; default Codex implementation workhorse at medium effort, fast/affordable tier for quick lookups, frontier only with a task-specific reason.
Only when building the matrix (or when the user asks to rebuild), before recording a chosen model, run probes in parallel with a 30 s timeout per model and a trivial non-interactive reply OK at low effort; record result, date and supported effort. PASS = exact OK reply, even if client cleanup overruns (record OK plus cleanup timeout); UNAVAILABLE = explicit error such as unknown model or usage limit; INCONCLUSIVE = timeout without OK. Re-probe an INCONCLUSIVE model once before considering an older model; never choose an older model over a newer one because of an INCONCLUSIVE probe alone. If still inconclusive, retain the current-model preference, mark availability unconfirmed and report the limitation.
Codex probe: timeout 30s codex exec --skip-git-repo-check -m <model> -c model_reasoning_effort=low "reply OK" < /dev/null
Claude probe: timeout 30s claude -p --model <model> --effort low "reply OK" < /dev/null
Keep models.md concise (~30 lines): each role (orchestrator, implementation worker, quick lookup, reviewer/verifier, cheap fallback) lists ORDERED options spanning both families (primary then fallbacks), model + effort + cost/capability reason + source/date + probe result/date. Keep login/usage-limited candidates in their preference order with availability noted; account access never determines permanent role order. Include cross-family reviewer alternatives for either author family.
An explicit model-specific client error (e.g. "requires usage credits") means UNAVAILABLE from THIS CLI login right now, not that the model needs credits in general. At build time record the message verbatim in models.md; for Claude record only authMethod from claude auth status, never email or tokens. During a run, if a model is not callable (e.g. account without Fable or Codex usage-limit error), use the next ordered option for that run and note the error and fallback in the task's _out.md History; do not edit models.md or automatically re-probe. Preserve the other-family verifier requirement; if no remaining suitable ordered option is callable, record blocked.
Workers do not spawn further workers unless their _in.md allows it; one level by default. Quick lookup/mechanical edits may use an own-family native subagent with low effort, selected from models.md.
Verification is always by the OTHER model family (Codex work checked by Claude, Claude work by Codex); a verifier is never weaker than the author. Escalate one level on failure; if the required family is unavailable, record verification as blocked.
